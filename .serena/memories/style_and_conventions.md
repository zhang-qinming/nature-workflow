# Style and conventions
- Python style is pragmatic and typed where useful; dataclasses are used heavily for resolved workflow configs.
- Config parsing errors should raise `ConfigError` from `src/paper_pipeline/dataprep/config.py`.
- Workflow builders return `list[Task]` and should keep tasks explicit and composable.
- For edits, prefer minimal, compatibility-preserving changes; do not change legacy behavior unless intentionally moving logic into `figures`.
- `figures` workflows should:
  - take explicit file/path inputs,
  - avoid implicit `data/...` workspace assumptions,
  - write stable outputs under `tables/`, `plots/`, `meta/`,
  - use deterministic IDs instead of random run IDs.
- Shell generators rely on environment-variable overrides rather than manual edits to generated files.
