# 全流程运行说明

本文档描述 workflow 之间的执行顺序、拆分策略与并行方式。完整的 workflow 名称列表见代码注册表 `src/paper_pipeline/workflows.py` 或 `paper-pipeline plan --config config.yaml <name>`。

## 聚合入口

- `all`：展开配置里出现的顶层聚合 workflow（`genebayes`、`perturbseq`、`plot`、`figures`）
- `genebayes`：prediction + feature merge + posterior training
- `perturbseq`：展开已配置的 `gene_level` / `cnmf_essential` / `cnmf_genomewide`
- `plot`：展开已配置的 `gene_burden` / `perturbseq_gene_level` / `perturbseq_cnmf` / `supplementary`
- `figures`：展开已配置的 `cnmf` / `program_heatmap` / `burden_volcano` / `gwas_manhattan` / `gene_level_scatter` / `cross_trait` / `gene_level_qq` / `program_rankings` / `gwas_locus_zoom` / `cross_trait_heatmap`

## GeneBayes 拆分

- `genebayes`：全链
- `genebayes-cpu`：只做 prediction + feature merge（可 CPU 并行）
- `genebayes-gpu`：只做 posterior training（消费 `genebayes-cpu` 的 `features.<trait>.tsv`）

三条 workflow 读取同一段配置 `workflows.genebayes.*`，只是子阶段与必需输入不同。

## cNMF 拆分与约束

essential 和 genomewide 两条链都支持三层拆分：

1. 全链（不带后缀）：`worker_indices` 和 `program_indices` 都必须全覆盖
2. `*-post`（postbase + association）：`program_indices` 必须全覆盖
3. `*-postbase-base`、`*-postbase-regulation`、`*-association`

只有 `*-postbase-regulation` 支持按 program 子集分片。推荐集群分片链路：
`prepare → factorize(按 worker 分片) → postbase-base → postbase-regulation(按 program 分片) → association`

## 推荐执行顺序

### 从零开始（最细粒度）

```
1.  genebayes（或 genebayes-cpu → genebayes-gpu）
2.  perturbseq-gene-level-prepare
3.  perturbseq-gene-level-limma（可按 chunk_indices 分片）
4.  perturbseq-gene-level-summarize
5.  perturbseq-cnmf-essential-prepare
6.  perturbseq-cnmf-essential-factorize（按 worker_indices 分片）
7.  perturbseq-cnmf-essential-postbase-base
8.  perturbseq-cnmf-essential-postbase-regulation（按 program_indices 分片）
9.  perturbseq-cnmf-essential-association
10. perturbseq-cnmf-genomewide-prepare
11. perturbseq-cnmf-genomewide-factorize（按 worker_indices 分片）
12. perturbseq-cnmf-genomewide-postbase-base
13. perturbseq-cnmf-genomewide-postbase-regulation（按 program_indices 分片）
14. perturbseq-cnmf-genomewide-association
15. plot-gene-burden
16. plot-perturbseq-gene-level
17. plot-perturbseq-cnmf
18. plot-supplementary
19. figures（可选）
```

### 中等粒度（后处理不细拆）

把第 7~9、12~14 步替换成 `perturbseq-cnmf-*-post`（前提：`program_indices` 覆盖完整范围）。

### 最小验证

```bash
paper-pipeline run --config config.yaml genebayes
paper-pipeline run --config config.yaml perturbseq-gene-level-prepare
paper-pipeline run --config config.yaml perturbseq-gene-level-limma
paper-pipeline run --config config.yaml perturbseq-gene-level-summarize
```

## 常见误区

- **`all` 不会重复展开子 workflow**：它只展开配置里实际出现的顶层聚合 workflow。
- **`perturbseq` 不是自动并行调度器**：如果 `worker_indices` / `program_indices` 设为子集又直接跑 `perturbseq`，会触发 cNMF 完整链的覆盖校验。
- **`project_root` 不改变输入输出解析规则**：`inputs.*` / `outputs.*` 的相对路径始终相对于配置文件目录解析。
